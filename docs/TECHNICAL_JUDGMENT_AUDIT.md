# テクニカル判断の実装監査と予測確認の範囲

指示文の設計点数は判断精度の実測値ではない。以下は2026-10-30の本体コード確認と限定入力検証に基づく。

| 対象 | 確認した実装・対応 | 未確認・限界 |
| --- | --- | --- |
| ローソク足PA | 終値突破、支持抵抗を試した後の実体を伴う反発/反落、別足での再試し、再試し失敗を既存実装で確認。移行局面を一足の局所押し戻りが上書きする分岐を、新しい解釈で修正 | 包み足等を追加したものではない。実体・ヒゲの大きさは記述量で、単独シグナルにしない |
| 時間足 | H4/M15・H1/M5の独立入力と品質照合は既存。新しい判断解説で確認足の逆行構造/逆行指標/局所無効化/未確認を区別して出力 | 確認足の逆行だけで基準足の転換としない。逆行が将来押し戻りで終わることを保証しない |
| 通貨強弱 | 既存の相対差・同期間の変化・通常幅との比較・逆行説明・Aの完成度への反映を確認。逆行時は価格側の方向構造・MACD経過・DMA持続の根拠と未完成を区別して解説 | 順位だけで反対売買を禁止しない。価格側の回復は通貨強弱自体の反転確認ではない |
| 予測/仕掛け分離 | 予測の確信度、A/B/C、優先状態、局所条件状態を別項目に保存。主予測撤回は基準足終値の水準へ結び付ける | A/B/Cや候補削減は勝率改善の証明ではない |

新規v12の`contextual_review_version=1`だけに補足解説と移行局面の条件順序修正を適用する。マーカーなしの旧v12とv11以前は当時の条件ルート・本文をそのまま復元する。指標設定、方向予測方式、価格余地条件、波の選び方はこの補修で変更しない。報告タスク指示は増やさない。

## 通常保存による限定の前向き確認

1. 初めて実際に新コードを使った通常収集を、run・コードcommit・評価時刻・非公開保存commit・snapshot blobで特定する。その時点の全32評価、方向、局面、主/代替経路、波の水準、条件を凍結する。旧方式の保存を新コードで再計算した結果を、当時出した予測と呼ばない。
2. その後に通常収集された確定足だけで照合する。M15/M5は局所条件、H4/H1は大局撤回・方向経過を確認。前回条件の照合は既存のfrozen followthroughを利用し、新しい取得・スケジュール・研究タスクは追加しない。
3. 公表後に完全に始まった足と、公表前の区間を含む足を区別する。欠損・出所未確認・未確定足を補間しない。目標/撤回の両方に触れた足の到達順序は未確認とする。
4. 方向の経過、主経路の条件到達、主予測撤回、局所仕掛け成立を分離する。単に次足が同方向だっただけで経路成功や取引利益としない。一般的な代替経路文の全体は機械的な正誤判定をせず、定義済みの水準・終値条件だけを照合する。
5. 観測された範囲と被覆を示す。必要な次の基準足がなければ結果待ち。保有期間や未定義の期限を作らない。少数例で的中率・期待値・普遍的な適切さを確定しない。

これは今回依頼された判断確認の範囲であり、終了した固定コホート、費用比較、発表前後研究を再開する指示ではない。
