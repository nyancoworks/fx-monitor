# FX Monitor

16通貨ペア × スイング/デイトレードの裁量判断支援プログラムです。自動発注・ポジション管理は行いません。

## 移行状況

公開コードと非公開データの分離移行は実施済みです。コード・Actionsは [fx-monitor](https://github.com/nyancoworks/fx-monitor)、価格原本・cache・snapshot・NY17・監視履歴は非公開の `fx-monitor-data` に保管します。旧 `fx-trading-system` はアーカイブ済みの履歴参照用です。

移行と定時運用の受入は完了しています。非公開側の `migration/READY.json` は原本照合・NY17復元・32評価検証、`collection_enabled=true`、`natural_operation_verified=true` を記録しています。現在は受入済み運用の保守を行います。過去の接続障害の内部原因が不明なことを、運用受入の未完了とは扱いません。

通知の到達は過去の対象枠について利用者申告で確認しています。API上のdeliveryはunknownで、今後の配信時刻や継続到達を保証するものではありません。最新の確認記録は [管理Issue #1](https://github.com/nyancoworks/fx-monitor/issues/1) と非公開運用記録を参照してください。

新しいGit履歴には市場データ・保存評価・実原本を含めていません。移行時の全体653テストと、後続開発の公開合成テスト件数は対象範囲が異なり、同一の検証件数として扱いません。

## 現在の本番機能と確認範囲

2026年10月30日時点の整理です。

- 16ペア×スイング/デイトレの全32評価を非公開保存。品質不足は評価保留として、候補なしと区別します。
- 価格構造とスーパーボリンジャーで環境、DMA・通常フィボナッチでセットアップ、ディナポリ係数MACD・Preferred Stochastic・RCIで勢いを補足します。多数決や全指標一致では判定しません。
- レンジ逆張りの運用・新規生成は廃止済み。PR #42のトレンド限定スイングは本番反映・新しい保存形式の自然採用まで確認済みです。H4のもみ合い背景を除外する定義と限界は [仕様](docs/TREND_SWING_POLICY.md) を参照してください。実相場でその除外分岐が作動した例は、まだ確認されていません。
- スイングのH4大局とM15仕掛け計画を分離します。[時間軸の仕様](docs/SWING_HORIZON.md)を参照してください。PR #44で実装済みですが、自然採用確認とは区別します。
- 経済指標・政策資料は補助情報。取得成功と鮮度・最新性・市場反応の検証を区別します。Finance Calendarは承認済みの既存refreshあたり最大2GETです。
- 定時報告と所有者限定Sitesの基本整備は完了。Sitesの一部の実機操作確認には限界が残ります。全文メール工程は取り下げ済みです。

PR #42の全272ローカルテスト成功と、通常収集での32評価復元・新形式保存の確認は別の証拠です。これらは利益・期待値・長期有効性の証明ではありません。

## 運用と保守

任意の固定期間追跡・価格参照・費用比較・発表前後価格研究は終了しました。専用のオフライン診断と、履歴保存時の研究用followup新規生成は削除済みです。定時本文に必要な前回比較・固定条件の経過確認は維持します。

- 定時判断と報告の不具合修正・依頼された機能追加を開発対象にします。
- 32評価の保存、3世代履歴、NY17足の復元、長期価格保管とinventoryは運用機能として維持します。保管方針の年数と実際の保有期間を区別します。
- 過去の保存評価を読む最小限のレンジ互換処理は維持し、新しいレンジシナリオは生成しません。
- `shadow`や`diagnostics`という名称でも、本番で呼ばれている足復元・指標・履歴処理は運用対象です。

## 非公開状態を使う実行

`FX_DATA_ROOT`に非公開データcheckoutの絶対パスを指定すると、保存入力・出力・原本の参照先を変更できます。未指定時は旧checkoutのレイアウトを維持します。

公開Actionsは`fx_system.private_runtime`から固定された処理を起動します。子プロセスの価格を含む出力とエラーは公開ログへ流さず、非公開checkout内の一時診断へ保存し、設定済みキー/トークン値を伏せます。これら一時診断はrunner終了後の永続保管を保証しません。保存評価の原本は非公開snapshot/履歴です。

収集workflowは`workflow_dispatch`のみで、所有者が`FX_COLLECTION_ENABLED=true`を設定するまでjobは実行されません。さらに非公開側の`migration/READY.json`で原本byte照合・完全NY17復元・正規32検証を確認するまで市場API呼出しへ進みません。非公開側の移行判定と自然運用受入は完了しています。これらの既存ゲートは維持し、確認目的の手動実行や収集頻度の増加は行いません。

運用で使用する所有者設定は`TWELVE_DATA_API_KEY`と、対象非公開データrepoだけにContents read/writeを付けた`FX_DATA_REPO_TOKEN`です。値をIssue・チャット・ログへ貼らないでください。既存時刻の起動先を置換する際は旧収集と二重実行しません。

直接`python -m fx_system.main`を実行すると市場API取得と詳細出力を伴います。移行確認や公開workflowの呼出しには使わず、上記の実行経路を使用してください。
